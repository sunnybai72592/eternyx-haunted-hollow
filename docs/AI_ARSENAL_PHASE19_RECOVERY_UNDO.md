# AI Arsenal Phase 19 — opt-in recovery undo

A user may explicitly opt in before confirming a selective recovery or full replacement. This captures the before and expected after local corpus, including exact decoded text, source order, identity, metadata, query, mode, filter and draft question. An unfinished search draft is preserved exactly. No-op operations do not produce a checkpoint. The checkbox starts unchecked and resets when the preview is invalidated or a recovery completes.

Only one checkpoint is held in component memory. A new confirmed recovery replaces it or discards it if unchecked. The checkpoint holds plaintext source data; this is not encrypted memory, secure erasure, durable backup or cloud persistence. Discard it when no longer required. File loading, file removal, clear workspace and search-setting edits proactively discard the checkpoint; even a failed file-load attempt conservatively invalidates it. Undo is independently blocked unless the live workspace exactly equals the expected after snapshot, and while backup or file operations are busy. Undo requires confirmation, restores the original documents and settings, invalidates derived evidence, search results, fingerprints and AI response state, clears the latest recovery receipt, and consumes the checkpoint. No redo, AI calls, network requests or backend changes. No prior remote AI request or chat history is revoked.

## Acceptance
Run the focused Phase 16–19 tests, full suite and app build. In browser, recover from both encrypted and plaintext backups with opt-in off and on. Test selective conflict copies and full replacement, including empty prior corpus and invalid/incomplete search drafts. Verify undo restores exact sources and settings, no redo is available, and the recovery receipt is cleared. Cancel recovery/undo and verify no mutation. Edit a search field, remove/add a source, discard or clear the workspace and verify checkpoint disappears. Test busy gates, new backup preview, new confirmed recovery, keyboard navigation and mobile. Closing/reloading the page loses the checkpoint; do not rely on it instead of downloaded backups. No live browser acceptance is claimed from source tests alone.
