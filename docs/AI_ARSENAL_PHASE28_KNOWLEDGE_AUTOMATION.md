# AI Arsenal Phase 28 — reusable knowledge validation

The rule editor creates explicitly user-defined templates of up to 20 rules. Versioned JSON templates can be copied and pasted for reuse, with strict schema and range checks, duplicate ID rejection, bounded text fields and confirmation before replacing an existing template. They are not executable scripts, scheduled jobs or saved automatically. Rules support presence, case-sensitive exact text, case-sensitive literal containment and inclusive numeric ranges with compatible units. The range engine reuses Phase 27 conversion arithmetic; converted values just outside a boundary within floating-point uncertainty require review rather than being silently accepted. No engineering or regulatory thresholds are supplied by the application.

Explicitly selected source documents are evaluated independently against each rule. All repeated observations must satisfy a value rule. Missing means no matching literal field extracted, not proof of absence. Unsupported units, incompatible dimensions and a source with excluded long field lines trigger review. The extraction limits apply to each selected source; a batch exceeding 4,000 referenced evidence observations is rejected without partial output. Results contain exact decoded source lines and offsets. A match is only against the specified rule and is not independent verification or a compliance certificate.

Changing the rule template, document selection or corpus invalidates the prior result. A status filter exposes matches, exceptions, missing fields and review rows. Counts-only reports omit evidence and template contents. Copying a template or full exception evidence requires explicit confirmation because it can disclose user thresholds, source names and text. No new AI call, runtime dependency, storage, upload, provider, scheduled execution or backend change is introduced.

## Acceptance
Run the focused Phase 16–28 regression workflow and full build/test suite. In browser create, edit, remove, export and import rules; verify invalid template rejection and declined confirmations. Use synthetic sources containing literal text, negative readings, compatible and incompatible units, exact inclusive boundaries, repeated values, missing fields, long excluded lines and evidence-limit overflow. Verify selection fencing, account changes, status filters, exact source lines, exception-only JSON and counts-only copying. Check keyboard/mobile and absence of network activity for local operations. Committed tests do not establish CI success, browser acceptance or compliance validity. No production deployment performed.
