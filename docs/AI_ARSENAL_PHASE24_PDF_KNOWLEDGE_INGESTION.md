# AI Arsenal Phase 24 — processed PDF knowledge ingestion

Reuse the existing AI Chat account PDF upload and process-document text-layer extraction pipeline. No new parser dependency, upload endpoint or provider is introduced. The Document Intelligence account PDF panel only reads on explicit user actions. It verifies the signed-in user, lists up to 50 owned ready PDFs, and retrieves at most 750 stored segments from a chosen ready PDF. Exact row count, contiguous zero-based segment indices, ownership, ready status, type, size and metadata are checked; incomplete or malformed snapshots are rejected. Readiness and ownership are rechecked after fetching. This is a reviewed snapshot, not a live synchronized copy or a transactionally consistent view of concurrent server-side changes.

The user can filter by reported page, preview exact stored text and explicitly select segments to copy into the existing local corpus. Valid leading page markers are labeled as reported; missing or invalid markers remain unknown. These legacy stored markers are not authenticated parser metadata and do not independently establish page provenance. Each selected segment becomes one local TXT source; its stable ID, filename suffix and original text retain the segment identity. Existing chunk overlap is preserved, not reconstructed into original pages. The same eight-source and character limits apply atomically. Local indexing, search, evidence review, RAG and backups operate on these copied text sources. Source line numbers and offsets refer to the extracted segment, not physical PDF layout.

The local workspace is keyed by authenticated account identity, with late-result suppression for document reads. Import invalidates previous search, fingerprints, backup previews, checkpoints, knowledge index and AI results. No new writes, deployment, OCR, AI requests or automatic uploads occur in the import panel. The original PDF and extracted text remain in account cloud storage; optional downstream AI synthesis still uses existing AI Chat credits and consent. Downloaded backups may contain imported text and should be protected.

## Acceptance
Run focused Phase 16–24 tests, full test suite and app build. In staging, use two synthetic accounts and existing processed PDFs: verify only owner-ready PDFs are listed, exact segment counts and Unicode preservation, reported/unknown page labels, duplicate and capacity rejection, sign-out/account-switch isolation, delayed request suppression, and fresh search/RAG citations. Test scanned PDFs and failed processing via the existing upload route. Confirm the read-only import creates no new storage objects, document rows or AI calls. Verify browser/mobile/keyboard use. Actual PDF extraction, staging RLS and live browser acceptance are not established by these source tests. Existing backend extraction must be deployed and functional for this integration to work.
