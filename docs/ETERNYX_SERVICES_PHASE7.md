# ETERNYX Services Phase 7 — Communication integrity and safe history

## This PR

Seven connected improvements in one pull request:

1. A *database-side* rate guard for customer/admin request messages:
   at most eight messages per actor and request per rolling minute.
2. Duplicate message suppression for identical text by the same actor in
   a 30-second window. Server-authored creation/status audit events bypass
   the rate limiter completely. Each user/request is serialized with a
   transaction-scoped advisory lock to prevent simultaneous submissions
   evading the limit.
3. A separate feedback limiter: at most four responses per user and
   scope review in a minute, plus 30-second exact repeat detection.
   Previously existing append-only RLS policies are retained.
4. Scope memos load in 20-review batches; feedback loads in 50-response
   batches. A count from the database controls genuine Load older actions.
   The prior hard first-100/first-200 truncation is removed.
5. Published scope history and response state are tied to the current
   signed-in account and request. Stale async responses are ignored;
   drafts and feedback state clear on account switching.
6. Admin scope publication rechecks is_admin() and the authenticated user
   immediately before insert; the underlying database RLS still enforces
   privilege. Database burst/duplicate failures receive human-readable,
   actionable feedback rather than misleading success.
7. Conversations and internal triage likewise clear stale account-specific
   data, verify credentials, and guard against outdated fetches; regression
   contracts cover these boundaries.

## Staging verification

- With authenticated customer A and customer B, test writing only to each
  account's owned request and prove cross-user reads/writes are denied.
- Send 8 messages to a given request within one minute: 9th should fail;
  a normal message after the cooldown should succeed.
- Send exact duplicate message within 30 seconds: rejection must explain
  the duplicate, without writing another event.
- Check an admin can publish an actual status update or a request creation
  despite rapid user messages: server-authored event triggers bypass throttles.
- Repeat with 4 scope replies in a rolling minute and a 5th attempt.
- Verify 21+ immutable scope memos and 51+ feedback events can be browsed.
- Switch account while reviewing a memo, conversation or internal triage:
  no prior session's content or draft is shown.
- Check mobile/desktop, reduced motion, keyboard controls, and no payment
  or service-delivery commitments.

No paid processing, contracts, pentest authorization or SLA is introduced.
