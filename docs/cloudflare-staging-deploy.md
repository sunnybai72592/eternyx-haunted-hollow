# Cloudflare staging static Worker deployment (Vite 5)

The Cloudflare build log reports Vite 5.4.19 compiled successfully; Wrangler auto-configuration then failed because the automatic Vite integration requires Vite 6+. No Vite upgrade is needed. A static-only Worker can serve the existing Vite output with explicit assets directory and SPA fallback.

**Use a separate Worker named eternyx-staging**, not the existing production Lovable site. In Cloudflare Workers & Pages, create or rename the staging Worker to match the explicit config. Connect the existing GitHub repo, branch main. Set build command to npm run build:staging (or leave empty if supported, because Wrangler custom build runs it). Deploy command: npx --yes wrangler@4.168.0 deploy --config wrangler.staging.jsonc. Root directory is repository root. Do not run generic npx wrangler deploy or create a production route. Static-only Worker, no server code or bindings. The default Vite build and production Lovable settings remain unchanged.

Set Cloudflare **build-time** variables (not only runtime Worker variables): VITE_SUPABASE_PROJECT_ID=mhodwvypfbxafamkrgsk, VITE_SUPABASE_URL=https://mhodwvypfbxafamkrgsk.supabase.co, VITE_SUPABASE_PUBLISHABLE_KEY=the staging project's active modern sb_publishable_ key. Never use a private key. The guard requires the exact staging URL and ref, disables browser OpenAI key and Stripe/Polar checkout flags, builds fresh dist, and scans text assets for the known production reference and common private-key patterns. A modern publishable key does not identify its project, so verify it came from staging. The scanner is a defense-in-depth check, not a comprehensive secret scanner or verification of all external integrations. The tool execution service now resolves the configured Supabase URL rather than a hardcoded production endpoint.

After deployment, record the actual workers.dev origin (example only https://eternyx-staging.ACCOUNT.workers.dev). Set DEVELOPER_STAGING_ORIGIN to that origin and DEVELOPER_STAGING_HOST to the exact hostname. Verify the manifest SHA, public deep links, security response headers, and run manual Developer Studio acceptance. Security headers and actual hosted browser acceptance are NOT certified by this deployment configuration. No production changes or paid infrastructure are authorized. Do not publish a production-connected staging build.
