# Developer Studio 4.7 — ordered API collection runner
Edit saved scenario names, method, URL, timing and media/JSON contracts without changing their identity. Duplicate within existing collection bounds and move checks within their own project; unrelated projects retain their positions. Saved URL normalization, credential exclusion and GET/HEAD-only constraints still apply. Edits and reordering invalidate configuration-bound run evidence. Before writes and execution, compare browser storage with the visible snapshot and refuse stale state (best-effort conflict detection, not atomic cross-tab locking).
The optional stop-on-first-failure policy is session-only. Actual requests remain sequential and explicitly confirmed. Unattempted checks are not represented as passes or failures. A partial run cannot export a full report or become a baseline. A failure on the last check is a completed failed suite. Existing default is run all. No automatic retries, scheduled jobs, authenticated access, production deployment or paid infrastructure.
