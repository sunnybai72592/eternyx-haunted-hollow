# Developer Studio 4.6 — multi-environment API integration

Saved project suites can run unchanged or with an explicit session-only development, staging or preview origin override. Overrides require one original origin; paths, request method and assertions remain unchanged, and queries and fragments remain stripped. Only canonical HTTPS origins (or explicit loopback HTTP origins) are accepted. Credentials, paths, queries and fragments in origin input are rejected. The displayed effective targets and the existing execution confirmation describe the actual destination; environment labels are not trusted verification of deployment or authorization. No network requests occur on selection, and no target configuration is persisted by this feature.

Changing environment or effective request definitions invalidates current run evidence. Regression baselines are stored separately per project and environment label (legacy records default to saved). The SHA-256 fingerprint binds effective URLs and contracts; changing the actual origin in the same slot also prevents comparisons. Up to 20 total baseline records remain supported. All comparison operations are local and metadata-only. Existing saved suite export continues to export original definitions. CORS, credential omission, redirect refusal, explicit run consent and bounded response reading remain in force. No hosted staging or production testing is performed by this change.
