# Developer Studio 4.8 — durable local API execution history

PR #797 completed the saved collection editor and ordered fail-fast runner. This wave journals an explicit execution start before sending requests, binds the effective suite to a SHA-256 configuration fingerprint and records ordered progress checkpoints and terminal receipts. Start-only/progress-only records survive reloads and mean no terminal receipt was recorded; they are not assumed to be either running or successfully completed. Completed, stopped-on-failure, cancelled and execution-error states are distinguished. History keeps at most 30 records across browser projects and stores no request URL, origin, name, raw signature, headers, bodies or response values. Project-scoped export and clearing are explicit. Local storage updates read latest records; not transactional or tamper-proof, no cross-device durability. A start write failure prevents execution; later write failures surface a warning, leaving live results available and unfinished evidence unverified.

Hosted public staging remains a separate gate: manually run .github/workflows/developer-staging-browser-acceptance.yml on main with pinned DEVELOPER_STAGING_ORIGIN and DEVELOPER_STAGING_HOST and confirmation RUN_DEVELOPER_STAGING_READ_ONLY. Require the verified summary artifact for the exact deployed revision, both viewports, direct routes and HTTPS provenance. The connector cannot dispatch the workflow or establish current staging run results. No hosted acceptance, protected runtime, database, publishing, collaboration or production certification is claimed.
