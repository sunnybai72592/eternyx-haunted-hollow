# AI Arsenal Phase 7 — AI-assisted agent plans, human-controlled

## What this change ships

1. Real, opt-in AI Chat step suggestions based on a human-provided goal and constraints. The existing authenticated chat backend, account entitlement and credit ledger are reused; no new provider is activated.
2. Separate opt-in AI quality/safety critique of a prepared local plan. The model may advise but cannot approve, schedule, execute or perform tasks.
3. Strict response parser: exactly one JSON object with 1–6 steps; each step must be research, draft or review, with bounded text. Unknown action kinds, IDs, execution statuses, tool grants, and extra fields are rejected.
4. Suggestions are shown for human inspection. A second explicit confirmation is required to import them into the local plan. On import, the existing createAgentStep validator issues new local step IDs, status stays proposed, and no external action occurs.
5. Edited goals, constraints, scopes, steps, or step ordering invalidate AI results and prevent stale suggestions from being imported.
6. No silent truncation: goal, constraint and prepared-plan review budgets are enforced before calling AI Chat. Optional AI Chat calls may consume existing ai.chat credits and save chat history; all local controls remain free.
7. Local plan download as plaintext, alongside existing copy, manual reordering, and scope checks.
8. Regression tests for malicious/overlong model outputs, unauthorized kinds/fields, human review gating, backend opt-in, and unchanged no-execution semantics.
9. AI Arsenal hub now describes the actual split between local agent planning, real AI advisory assistance, and disabled external execution.

## Boundaries

- This does NOT deliver autonomous agents, background execution, external writes, payments, computer control, live web research, code execution, or tool authorization. No arbitrary model output is executed.
- AI suggested steps are drafts, not verified facts or approved work. Suggested kinds cannot include external_action or paid_action, and model-supplied permissions and execution status are never trusted.
- The existing chat bridge contacts the configured AI provider only on a user click. Chat messages may incur existing ai.chat charges and are stored as regular chat history. The app does not automatically retry.
- Manual plans remain local until explicitly submitted for an AI chat critique, or exported by the user; local edit and export operations do not contact a provider.
- No AI Video changes. Native scanned-PDF OCR and embedding-based semantic search remain separate validated-infrastructure milestones.

## Staging acceptance

- Run CI with the new parser tests, app build, and desktop/mobile acceptance.
- With consented test data, verify suggestions are actually generated by the configured chat service, then require human validation and a separate import confirmation.
- Attempt to inject JSON containing external_action, paid_action, permissions, status executed, IDs, oversized steps, or seven steps. Confirm fail-closed with no imported changes.
- Check plan review of a normal draft and a draft over 3,200 characters; the latter must refuse without submitting or truncating.
- Confirm every imported suggestion remains proposed, cannot grant scopes, and does not execute anything, including through navigation or refresh.
- Verify invalidated responses after goal/constraint/step edits and the absence of hidden retries.
- Test unauthenticated, insufficient credit, subscription entitlement and provider failure handling, plus copied/exported plan text.
- Staging validation of the configured chat backend and credit accounting is required; passing frontend tests alone is not production verification.
