# Docker signed agent heartbeat: real, private-key authenticated reporting

PR follows merged Docker agent identity enrollment. This is push-only signed telemetry from an operator-owned workstation/host, **not remote Docker control, independent machine attestation, or multi-tenant execution infrastructure**.

## Improvements in this milestone

- Account/workspace-bound agent identity, reusing the enrolled Ed25519 public key.
- A real CLI that queries the host's local Docker Engine (never remote TCP/SSH daemon) and signs a bounded engine response.
- Strict canonical versioned signed message binding agent UUID, UTC timestamp, 32-byte nonce, Engine response, version and optional count.
- Server-side Ed25519 verification, agent key-revocation checks and atomic SQL clock/replay/frequency guards.
- Owner-isolated reports and recent (24 retained) audit entries under RLS.
- Signed report freshness displayed to the owner: recently reported, stale, unavailable, never reported, revoked. No fake online state.
- No user-visible Docker socket, CLI output, secret key, container names, image details, logs or host address are uploaded.

## Deployment prerequisites

Apply the migration `20261123030000_docker_workspace_enrollment.sql` first, then `20261123040000_docker_agent_signed_reports.sql`, on a **staging** Supabase database. Run ownership/replay/clock and permission integration checks. Deploy authenticated `docker-enrollment` and the new `docker-heartbeat` Edge Function. Configure `[functions.docker-heartbeat] verify_jwt = false` because it uses mandatory independent Ed25519 signatures, **not JWTs**. This is not a publicly usable unauthenticated mutation endpoint.

## Send a real report

Register the agent through `/integrations/docker-enrollment` first, using the key generated by `scripts/docker-enrollment-key.mjs`.

On that trusted operator machine with Node.js 20+ and access to **its own local Docker Engine**:

```sh
export ETERNYX_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
node scripts/docker-agent-heartbeat.mjs YOUR_ENROLLED_AGENT_UUID /ABSOLUTE/PATH/docker-agent.pem
```

If your gateway requires a publishable API key, set `ETERNYX_SUPABASE_PUBLISHABLE_KEY` with the PUBLIC key only. NEVER supply an admin/service key. The report includes engine availability, its version and bounded container count; no names, logs, environment variables, images, IP addresses or paths are sent. The private key is never uploaded.

Calls can be repeated manually (not a daemon, scheduler or background job). Reports closer than 15 seconds, signed outside a narrow clock window, duplicated or out of order are rejected. A successful signed report records **what the enrolled key claimed to observe**. It is not independent proof the key is on the described host or that Docker has been securely attested.

## Security & production acceptance

RLS enforces owner-only SELECT on report/audit tables; SQL accepts writes only from trusted service-role infrastructure after Edge signature verification. Revoked agents cannot report. Use short-lived authentication tokens for the browser. The Edge endpoint does not expose Docker management APIs or implement external inbound connectivity.

Before production: run migration through Supabase staging workflow, deploy both Edge Functions, test RLS as owner A/B, signed valid/invalid/replayed/expired/concurrent reports, revocation, actual Docker availability, inspect advisors, and verify CORS/rate limits with your proxy. CI tests are regression checks only, not substitutes for live database validation.

Further work: signed mTLS/attestation, ownership checks, durable gateway audit, quotas and a separately reviewed tenant-safe command protocol before any remote container actions.
