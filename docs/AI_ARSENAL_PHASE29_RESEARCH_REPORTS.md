# AI Arsenal Phase 29 — comparative local research

An explicit local research plan contains a title and up to six questions, each with a separate literal search query and all/any mode. Versioned plan JSON supports strict validated import and confirmed clipboard export. Questions are labels, not instructions executed by a language model. The current selected corpus is indexed once with existing BM25; each question is searched per selected source using that shared index. The report provides per-source total matches and up to two ranked passages per question/source pair, including empty results. No match is not proof of absence. This is lexical research, not autonomous web research or semantic synthesis.

Select up to 24 question/passage pairs, inspect exact decoded source text and half-open UTF-16 coordinates, and optionally enter up to 1,000 characters of human-authored notes per question. Notes are unverified. Selection is distinct per question; repeated references across questions are intentional. Evidence JSON includes plan questions, source metadata, retrieval counts, selected extracts and notes, with separate optional date evidence. A counts-only report omits source names, queries and excerpts. Export requires explicit review and confirmation where private contents are included.

The timeline identifies standalone literal YYYY-MM-DD mentions, checks Gregorian dates including leap years, sorts valid mentions chronologically and displays up to the earliest 100 occurrences. Invalid candidates and total valid counts are reported. Long source lines retain an exact date-centered excerpt up to 400 characters with decoded offsets. Repeated dates remain separate mentions. Ambiguous date formats, timestamps and inferred events are not interpreted; a printed date is not proof of an actual event.

Editing the plan, changing selected sources, replacing the corpus or discarding results invalidates research results, selections and notes. No new runtime dependency, upload, network request, AI provider, backend change, automatic scheduling or production deployment.

## Acceptance
Run focused Phase 16–29 regressions and the full build/test suite. In browser verify plan creation, invalid imports, selected-source searches, all/any matching, missing evidence, source coordinates, repeated and invalid leap dates, long-line excerpts, timeline limits, selection cap, human notes, declined export confirmations, private export contents, counts-only reports and stale-state invalidation. Verify keyboard/mobile, account changes and absence of network activity for local research. Test creation does not establish CI success or live browser acceptance.
